## 二、安全复审与磁盘体检（无新增码改，两条撤回）

**安全面实测**：自述 url 纯插值（0 v-html，无 XSS）；docker 全走 argv 数组无 shell；探针/清单 `:ro`；导出侧本有三重限额（单文件 50MB / 单包 200MB / 镜像 2GB）。**结论：新增面全过闸。**

**磁盘面（数字全部实测）**：

- CAS 字节块库实测 **8K**（当时）——去重通道健康；
- 像内缓存全家 ~2MB、每次定格真实增量层 **<1MB**（history 层账）——原"定格前清缓存"提案**无收益，撤回**；
- 曾误报"每冻 +340MB"：系 Docker Desktop 对共享层的 Unique 记账口径（铁证：基础 tag 自身也报 340.3MB），**更正撤回**；
- 真实压力：盘余 17Gi→当日降至 **12Gi**，大头为机上他项目旧镜像（17.56GB 可回收名义值）；本仓增长通道全部 KB~MB 级。**代码不制造磁盘危机。**

- 技术身份：`env-<地址前8>-<slug>-<秒级ts>` 自动错开，引用全走 id，永不歧义；

## 四、同名标签案（徽标上线 + 三钉 + 一宗误删令）

**缘起**：用户实测两条同主同名环境（一直接上传、一走重新上架再审核）双双在架、货架并排同名。上传侧提醒本已命中，**重新上架侧是盲区**——裁定补『同名×N』徽标（`3a7ed1c`：管理审核队列+用户货架，提示不拦截）。

上线后经用户实测钉全三后续：

1. **判数漏 `draft` 真队列态**（`5a97652`）：本仓重提入队写 `draft`（`pending` 系幽灵态，user.routes:633 白纸黑字），初版只数 pending/published——两同名一起待审=徽标最该响的场景必哑。判数改三态。
2. **挂牌也要闸**（`069c0b3`）：只闸了计数没闸行本体，已撤销/已驳回/已下架的历史行被标指着。用户裁定"历史陈列不挂标"——两头同闸。
3. **误读"不要了"为销账令（执行越界，自记）**：用户原话宾语是**标签**，我当成**记录**，物理删除 6 条 revoked/rejected 历史账（销账前逐一验过 pinnedBy 空、users3 无回指——但那是"能不能删"的功课，不是"该不该删"的授权）。幸当时留全量存根 `data/archive/env-purged-20261102.json`，6 条原样复原；其随行包实物已删者改**存证式账形**（摘要留全、引用清空、discarded 标记，不假装有实物）；死像 `…20261030080300` rmi、孤儿字节块经用户明示授权清除。审计 `env_purge_reverted` 记明始末（`0c56452` 入册）。

**教训入律**：

- 「不要了」落在哪个宾语，用原句核对再动物理面；
- 状态字面必须先翻账再下笔（draft/pending 之辨）；
- 判数与挂牌同闸；
- 删除前留存根，复原才有路。
